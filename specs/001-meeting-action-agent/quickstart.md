## 3. 설치 [가능]

의존성 파일(`requirements.txt`, `pyproject.toml`)은 아직 없다. 지금은 계약 검증에 필요한 패키지만 설치한다.

```powershell
cd C:\work\과제
python -m venv .venv
.venv\Scripts\Activate.ps1

```

가상환경이 PowerShell 스크립트 실행 정책 때문에 활성화되지 않으면, 활성화 없이 `.venv\Scripts\python.exe`를 직접 호출한다.

STT(Whisper 계열), 화자 구분, LLM 호출 라이브러리는 선택이 끝나지 않아 목록에 넣지 않았다 (`research.md` R-01, R-02, R-05).

## 4. 계약 검증 실행 [가능]

`contracts/`의 스키마 10개와 예시를 검사한다. 정상 예시는 통과, 오류 예시는 거부되어야 한다.

```powershell
python specs\001-meeting-action-agent\contracts\validate_examples.py
```

기대 출력:

```text
스키마 10개 | 정상 예시 12개 | 오류 예시 17개 | 모두 기대대로
```

- 종료 코드 0이면 모두 기대대로, 1이면 어긋난 예시가 있다. 어긋난 예시는 `FAIL`로 표시된다.
- 스키마를 수정했다면 이 검사를 다시 실행한다. 새 규칙을 넣을 때는 그 규칙을 어기는 예시를 `examples/invalid/`에 추가하고 `_manifest.json`에 어느 스키마로 검증할지 적는다.
- 어느 위치에서 실행해도 된다 (스크립트가 자기 위치를 기준으로 한다).

## 5. 프로젝트 폴더 준비 [예정, T-00-2 ~ T-00-4]

0.CLAUDE.md의 프로젝트 구조대로 아래 폴더를 만든다. 이 폴더들은 아직 없다.

```text
audio/                 # 원본 녹음 (신규 생성만, 수정·삭제 차단)
transcripts/original/  # 원본 녹취 (신규 생성만, 수정·삭제 차단)
meetings/              # 회의 분석 결과
actions/               # Action List, review_queue/
docs/
tests/
.claude/               # agents/, skills/, settings.json
```

**원본 보호를 먼저 설정한다.** `audio/`와 `transcripts/original/`에 어떤 파일도 넣기 전에 deny 규칙과 Hook이 동작하는지 확인한다 (T-00-3, T-00-4). "신규 생성 허용, 덮어쓰기·삭제 차단"을 deny 규칙만으로 만들 수 있는지는 확인이 필요하다 (`research.md` R-08).

## 6. 테스트 실행 [예정, T-00-8]

pytest 구성이 끝나면 저장소 루트에서 실행한다.

```powershell
python -m pytest tests -v
```

테스트는 세 종류로 나뉜다 (`plan.md` 6장).

| 종류 | 대상 | LLM 필요 |
|---|---|---|
| 단위 | 상태 전이표, 완료 가드, 기한 환산, 계약 스키마, Reviewer 코드 검증기 | 아니오 (항상 실행) |
| 정답표 기반 | 지시 추출, 이행 판정 vs 정답표, 재현율·상태 일치율 | 고정 응답 fixture 또는 실제 호출 |
| 안전장치 | 원본 덮어쓰기·삭제 시도 차단, 직접 파일 편집으로 `완료` 변경 시도 차단 | 아니오 |

정답표는 `docs/answer_key.md` 또는 `tests/fixtures/`에 둔다 (T-00-6). **필수 기준**(허위 담당자·기한·Action 0건, 무승인 `완료` 0건, 제안·질문 Action 0건)을 어기면 실패다. 재현율 90%, 상태 일치율 80%는 초기 목표이며 튜닝 대상이다 (SPEC 16장).

실제 LLM 호출 테스트는 비용과 변동성 때문에 기본 실행에서 분리할 예정이다. 분리 방식(마커 등)은 R-05 결정 후 정한다.

## 7. 사용 흐름 [예정]

SPEC 15장의 시연 시나리오이다. 아래 흐름이 구현되면 실행 방법을 이 절에 적는다. 명령과 화면은 확정되지 않았다.

**1단계 — 신규 회의**
1. 회의 메타데이터를 입력한다. `meeting_id`, **`meeting_date`(필수, 기한 환산 기준)**, 선택으로 `title`, `participants`, `speaker_map`.
2. 녹음(MP3/WAV/M4A, 한국어, 최대 2시간)을 올리거나, 개발 중에는 가짜 녹취 JSON을 입력한다.
3. 회의 요약(핵심 논의·결정·미결)과 지시 후보가 만들어진다.
4. Reviewer가 모든 Action을 녹취 원문과 대조한다. 통과한 Action은 Action List에 저장되고, 2회 재시도 후에도 반려된 건은 **사람 확인 큐**로 간다.

**2단계 — 다음 회의**
1. 다음 회의 녹취와 함께 **이전 Action List를 직접 지정**한다 (회의 시리즈를 자동으로 추론하지 않는다).
2. `완료`가 아닌 모든 이전 Action에 대해 이행 발언을 찾아 `완료 후보 / 진행중 / 미완료 / 확인 필요`로 분류한다. 판단마다 신규 회의의 원문·화자·타임스탬프가 붙는다.
3. 사람이 완료 후보를 건별로 확인한다: `[완료] [계속 진행] [확인 필요]`. **승인자 이름을 입력해야** `완료`가 저장된다.

## 8. 꼭 알아둘 규칙

- **Agent는 Action을 `완료`로 만들지 못한다.** `완료 후보`까지만 제안하고, 사람이 승인해야 `완료`가 된다. 승인값 없이 `완료`를 저장하면 저장 계층이 거부한다.
- **담당자·기한이 녹취에 없으면 `확인 필요`로 둔다.** Agent가 추정하지 않는다. 기한을 명시적으로 미정이라 한 경우만 `미정`이다.
- **원본 녹음·원본 녹취는 수정·삭제하지 않는다.** 보정본 등 파생물은 `transcripts/original/` 밖에 저장한다.
- 테스트 데이터는 **가상의 회의**만 쓴다. 실제 회사 회의 녹음·녹취를 넣지 않는다.
- 필드를 바꾸려면 SPEC.md를 먼저 수정한다. `contracts/`는 SPEC을 따라가는 파생물이다.

## 9. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| `ModuleNotFoundError: jsonschema` / `referencing` | 3절의 설치 명령 실행. 가상환경을 활성화했는지 확인 |
| `ModuleNotFoundError: pytest` | `python -m pip install pytest` |
| 콘솔에서 한글이 깨짐 | 파일은 UTF-8이다. 콘솔 인코딩 문제이므로 `$env:PYTHONIOENCODING = "utf-8"` 설정 후 재실행 |
| `.venv\Scripts\Activate.ps1`이 실행 정책으로 차단됨 | 활성화 없이 `.venv\Scripts\python.exe`를 직접 호출 |
| 검증 스크립트에서 `FAIL invalid ...: 거부되어야 하는데 통과했다` | 스키마 수정으로 규칙이 느슨해졌다는 뜻. 해당 규칙을 복구하거나 SPEC과 함께 예시를 바꾼다 |
