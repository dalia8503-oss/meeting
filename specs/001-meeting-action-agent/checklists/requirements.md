- [x] CHK021 정량 기준 "제안·질문을 Action으로 생성 0건"과 5.5 "애매하면 Action + `지시여부애매`"가 충돌하지 않는다
  - **결정됨 (2026-11-11, MVP)**: 명확한 지시·요청 → 후보 생성 / 명확한 자발적 약속 → 후보 생성 / **명확한 제안 → 후보 없음** / **단순 질문 → 후보 없음** / 지시인지 제안인지 애매 → 후보 생성 가능(`instruction_type="지시여부애매"`, flags `지시여부애매`, status `확인 필요`) / 조건부 지시 → 후보 생성(`조건부`, flags `조건부`, status `확인 필요`). 정답표상 명확한 제안·질문이 Action(애매 포함)이 되면 필수 기준 위반이며, `지시여부애매`는 정답표상 지시/제안 구분이 실제로 애매한 발언에만 허용한다. 제안·질문은 `open_issues`에 기록한다.
- [ ] CHK022 `low_confidence` 발언이 **지시 추출**에 미치는 영향이 정의돼 있다
  - **미충족**: US-01과 5.6은 이행 판정에서 `확인 필요`로 둔다고 하지만, 지시 추출 단계에서 `low_confidence` 발언만 근거인 Action의 처리는 없다.

  - **미충족(경미)**: US-04는 "진행 중", 상태 값은 "진행중"이다. 값은 `진행중`으로 `contracts/`에 고정했으므로 SPEC 본문 표기만 맞추면 된다.
- [ ] CHK024 `기한경과` 판정 기준이 정의돼 있다
  - **미충족**: 5.6은 "기한이 지났으면 `기한경과` 표시"라고 하지만 비교 대상이 없다. `due_date_normalized`가 null(요일 외 범위 표현, "다음 회의까지", `미정`, `확인 필요`)이면 판정할 수 없고, 신규 회의 날짜(`meeting_date`)와 비교하는지도 쓰여 있지 않다. `진행중` 외 `미완료`에도 붙는지도 불분명하다.
